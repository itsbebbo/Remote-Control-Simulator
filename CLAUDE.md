# CLAUDE.md

Guidance for Claude Code working in this repository.

## What this project is

A PlatformIO/Arduino firmware for the **M5Stack Core2** that acts as a bench
transmitter for **CRSF** (TBS Crossfire). It sends `RC_CHANNELS_PACKED` frames at
50 Hz out of Port A and decodes the telemetry a flight controller sends back. The
touchscreen UI is **LVGL 8**.

There is exactly one firmware, one board env, and one source file. No tests, no
host-side tooling, no CI.

### Safety constraints — read before editing channel behaviour

This tool is wired to a live flight controller. In the `CHANNELS` table
([main.cpp:119](src/main.cpp#L119)) CH7 is `ARM` and CH8 is `FIRE`, both
two-position switches that default to `CHANNEL_MIN` (1000) and that the UI can
drive to 2000. Several deliberate decisions exist only for safety:

- Every channel powers on, and returns on RESET, to its own `defaultValue` — not
  to a blanket 1500. Switches land on a detent; `Thrust` rests at idle (1000).
- Channels without an on-screen control (everything outside `PANEL_CHANNELS`,
  including all four sticks) are still sent in every frame, pinned at their
  defaults. They cannot be moved from the UI at all.

Do not change defaults, the reset path, or which channels are on the panel as an
incidental part of some other change. If a task requires it, call it out
explicitly.

## Build and upload

Build from the PlatformIO toolbar in VS Code and everything just works — the IDE
extension puts `C:\pio\penv\Scripts` on PATH for its own tasks.

From a shell it does **not**: `pio` is not on PATH, and the build dies at the
`bootloader.bin` step with `'esptool' is not recognized`, because the platform
invokes `esptool` by bare name and relies on PATH to resolve it. One prepend fixes
both problems at once (verified):

```bash
# Bash
PATH="/c/pio/penv/Scripts:$PATH" pio run
```

```powershell
# PowerShell
$env:PATH = "C:\pio\penv\Scripts;$env:PATH"; pio run
```

Then `pio run -t upload` to flash, and `pio device monitor` at 115200 for serial
(the firmware prints nothing — `CORE_DEBUG_LEVEL=0`).

**Use `C:\pio\penv`, not `C:\Users\Mark\.platformio\penv`.** Both exist and both
contain a `pio.exe` and an `esptool.exe`, but they are different toolchains, and
the second one is a leftover from a stock PlatformIO Core install:

| | `C:\pio\penv` (correct) | `C:\Users\Mark\.platformio\penv` (stale) |
| --- | --- | --- |
| PlatformIO Core | 6.1.19 (was 6.2.0 until 2026-09-25) | 6.1.19 |
| esptool | 5.0.1 — matches pinned `tool-esptoolpy` | 5.4.0 |

Building via the stale one succeeds and is therefore easy to miss, but it silently
images the firmware with an esptool the platform never pinned. `PLATFORMIO_CORE_DIR`
is `C:\pio`, so that is the tree everything else already resolves against. Because
the core in `C:\pio\penv` changed version, every build prints an "Obsolete PIO Core"
banner. It is harmless; the thing to check is that esptool stays 5.0.1.

**The compiler is installed by `idf_tools.py`, and that refuses to run under Git
Bash / MSYS** ("MSys/Mingw is not supported"; it keys off `MSYSTEM`). pioarduino
only ships `toolchain-xtensa-esp-elf` as a stub (`package.json` + `tools.json`), and
the real compiler is extracted to `C:\pio\tools\toolchain-xtensa-esp-elf` on first
use. If that step fails, the build prints `idf_tools.py installation failed` and
then `'xtensa-esp32-elf-g++' is not recognized`. The fix is to run the install
once from PowerShell. After that, Bash builds work:

```powershell
$env:IDF_TOOLS_PATH = "C:\pio"; $env:IDF_PATH = ""
C:\pio\penv\Scripts\python.exe C:\pio\packages\tool-esp_install\tools\idf_tools.py `
    --non-interactive --tools-json C:\pio\packages\toolchain-xtensa-esp-elf\tools.json install
```

`scripts/limit_build_jobs.py` (a `pre:` extra script) forces `num_jobs = 1`.

**Build artifacts live off Google Drive.** `platformio.ini` sets
`workspace_dir = C:/pio/workspaces/Crossfire-Tester`, because the Drive sync client
locks `firmware.bin` mid-build and would otherwise sync every object file. Keep it
that way. Current footprint: ~11% flash, ~2.3% RAM.

### Pinned dependencies, and why

- `platform` = pioarduino platform-espressif32 55.03.30 — ships arduino-esp32 3.3.x.
- `m5stack/M5Unified@^0.2.0` — **not** the older M5Core2 library, which only builds
  against arduino-esp32 2.x. Board access is `M5.Display`, `M5.Touch.getDetail(0)`,
  `M5.BtnA/B/C`.
- `lvgl/lvgl@^8.3.11` (resolves to 8.4.0). This is LVGL **8**, not 9 — the v8 API
  (`lv_disp_drv_t`, `lv_btn_create`, `lv_btnmatrix_*`) is what the code uses.
- `-DLV_CONF_INCLUDE_SIMPLE` plus `-I include` is what makes LVGL pick up
  `include/lv_conf.h`.

## Architecture

### Two cores, by necessity

LVGL redraws block for tens of milliseconds. Sharing one loop with the RC stream
would stretch the gaps between frames far enough to risk a failsafe on the flight
controller, so the link is pinned to the other core:

- **Core 0** — `crsfLinkTask` ([main.cpp:313](src/main.cpp#L313)), priority 3,
  4096-byte stack. Wakes every 5 ms via `xTaskDelayUntil`, drains the UART, and
  sends an RC frame every 4th poll (20 ms = 50 Hz).
- **Core 1** — the Arduino `loop()` ([main.cpp:665](src/main.cpp#L665)): BtnB, `updateStatus()`, `lv_timer_handler()`, `delay(5)`.

### Shared state — no locks, on purpose

Three `volatile` globals cross the core boundary. There is no mutex and no queue;
correctness rests on each being a single naturally-aligned word that a reader
therefore never sees half-written. Preserve that property.

| Variable | Writer | Reader |
| --- | --- | --- |
| `channelValues[16]` (`uint16_t`) | UI, core 1 | link task, core 0 |
| `lastTelemetryMillis` (`uint32_t`) | link task | UI |
| `batteryDecivolts` (`int32_t`) | link task | UI |

If you need to add shared state, keep it to one aligned word or introduce real
synchronisation deliberately — don't add a wider struct and hope.

### CRSF link

`Serial2` (UART2) at 420000 8N1, not inverted, TX on GPIO32 / RX on GPIO33
(Port A). The explicit pins matter: the defaults 16/17 are used by the Core2 PSRAM.

- `crc8()` ([main.cpp:211](src/main.cpp#L211)) — poly `0xD5`, computed over
  type + payload (`&frame[2]`, `length - 1` bytes).
- `sendCrsfFrame()` ([main.cpp:223](src/main.cpp#L223)) — packs 16 channels ×
  11 bits, LSB first, mapping 1000–2000 µs onto 172–1811 ticks. Sync byte `0xC8`.
- `receiveCrsfFrames()` ([main.cpp:272](src/main.cpp#L272)) — a small state machine
  over `fill`: hunt for a valid sync byte, validate the length byte (2–62), then
  collect. A partial frame that stalls for 10 ms is abandoned and resync restarts.
- `handleReceivedFrame()` ([main.cpp:258](src/main.cpp#L258)) — CRC-checks, stamps
  `lastTelemetryMillis`, and decodes only battery sensor frames (`0x08`) today.

Link state in the header: `NO FC` when no CRC-valid frame has arrived in 1 s,
`FC OK` once frames arrive, `FC OK 12.4V` once battery frames decode.

### UI model

320×240, rotation 1, 40-line draw buffer, dark palette defined as `COLOR_*`
constants. One fixed screen with no paging: a header, four rows and a footer.

`PANEL_CHANNELS` ([main.cpp:141](src/main.cpp#L141)) lists the channels that get a
row, in order: ARM (CH7), FIRE (CH8), Cam Servo (CH9) and Contrast (CH11).
`createUi()` builds the rows once. Each row is a name on its own line above either
an `lv_slider` (continuous) or an `lv_btnmatrix` (switch, `one_checked`), plus a
value readout. `rows[slot].channel` is the slot→channel map; callbacks receive the
**slot** index smuggled through `user_data` as a `uintptr_t`.

Readouts show **percent deflection** (`-100%`…`+100%`), not microseconds —
`formatChannelValue()` ([main.cpp:359](src/main.cpp#L359)). A channel away from its
default is tinted amber (`channelTint`). Tapping a readout resets that one channel
to its default (`resetSlot`). `RESET` (or BtnB) resets all sixteen and pushes the
defaults back into the four controls in place.

The footer holds only `RESET`, centred over the Core2 BtnB zone so the bezel button
and the on-screen one line up. BtnA and BtnC do nothing. `readTouch` discards
touches with `y >= 240`, which is the digitizer strip below the panel that drives
the bezel buttons.

### Adding or re-mapping a channel

Edit the `CHANNELS` table ([main.cpp:119](src/main.cpp#L119)) — name, control kind,
switch position count, default. To show or hide a channel, edit `PANEL_CHANNELS`.
Four rows exactly fill the space between header and footer, so a fifth needs a
layout change (smaller `ROW_H`, or paging back). An empty name falls back to `CH n`. Switch channels
only ever emit evenly spaced detents (`switchPositionValue`), so 2 positions give
1000/2000, 3 give 1000/1500/2000, and 6 give 1000–2000 in 200s; a switch can never
rest on an intermediate value the receiving end would have to interpret. A new
position count also needs an entry in `switchMap()` and a static map array —
`lv_btnmatrix` keeps a *pointer* to the map it is given, so those arrays must
outlive the matrices built from them (hence file scope). A `CONTROL_SWITCH` with
fewer than 2 positions is broken: every button would send the default.

`CHANNEL_COUNT` is 16 and cannot grow — `RC_CHANNELS_PACKED` carries exactly 16.

## Landmines

Each of these is already a comment in the source. They bite again if removed.

- **`LV_TICK_CUSTOM 1`** in `lv_conf.h` is what feeds LVGL its time base. Without
  it no timer fires, nothing draws, touch is never polled, and the screen is blank.
- **`LV_USE_SPINNER 0`** must accompany `LV_USE_ARC 0`. Spinner defaults to on and
  hard-errors without arc.
- **`LV_COLOR_16_SWAP 0`** keeps `lv_color_t` byte-compatible with
  `lgfx::rgb565_t`, which is exactly what `flushDisplay` casts to for M5GFX.
- **`LIST_HEIGHT`, not `LIST_H`** — FreeRTOS `list.h` uses `LIST_H` as its include
  guard. Watch for this class of collision with any short all-caps name.
- **`LV_PART_*` and `LV_STATE_*` are separate unnamed enums.** OR them only after
  casting both to `lv_style_selector_t`; combining them directly is a deprecated
  enum-to-enum bitwise operation.
- **`constrain()` is a macro**, so evaluate `map()` into a local first rather than
  nesting the call — see `sendCrsfFrame`.
- `updateStatus()` diffs against a static `lastText` before touching the label, to
  avoid re-laying out the header 200×/second.

## Conventions

The existing style is consistent and deliberate; match it.

- Anonymous namespace around everything except `setup()`/`loop()`. Nothing leaks.
- `constexpr` for every constant, grouped under banner comments
  (`// ---- wiring --`, `// ==== CRSF link ====`). No magic numbers inline.
- `camelCase` functions and variables, `SCREAMING_SNAKE` constants, explicit
  `static_cast` rather than C casts.
- Comments explain **why**, not what — the non-obvious constraint, the hardware
  quirk, the reason an alternative was rejected. Keep that bar; don't add narration
  of what the next line plainly does.
- Four-space indent, ~90 column soft wrap, braces on the same line.
